状态：append-only 审计记录

## 1. 定位

本文档按会话顺序保留用户直接提出的产品、验收、开发流程和配置需求原话，用于追踪需求来源、识别后续变更和复核归一化结果。

本文档是溯源证据，不是 CoordPlane 产品行为的第二事实源。可执行产品合同仍只由 `README.md`、`core.md`、`runtime.md`、`git.md` 和 `acceptance.md` 五份规范定义。原话与当前规范冲突时，不得直接选一边实现；必须先归一化、经需求审批后更新五份规范。

## 2. 记录规则

1. 从本文档创建起，用户任何新的产品、验收、开发流程或配置需求，都必须先按接收顺序追加到本文档，再进行需求归一化、设计、实现或验收。
2. 每条记录使用单调 `UR-NNNN` ID，保留用户原有用词、大小写、标点、路径和换行；不在引文内改写错别字、翻译、摘要或补充解释。
3. 已记录条目不得删除、重排、覆盖或静默修正。用户后续纠正、撤回或替换需求时，追加新条目并记录 `supersedes`/关联 ID，旧原话继续保留。
4. 归一化需求变更必须在五份规范、issue 或冻结收据中引用对应 `UR-NNNN`；一条原话可映射多个规范不变量。
5. 用户明确标注为参考且未形成新决策的粘贴材料不作为新需求重复回填；其中若包含用户新增的明确要求，该用户原话仍必须记录。
6. 真实 token、密码、私钥、session cookie 或其他凭据不得写入 Git。这是原话保留的唯一内容例外：以 `[敏感凭据未入库]` 替代原值，记录脱敏原因和不可逆摘要，不保存可恢复值。
7. 每次冻结需求必须记录本文档 Git blob SHA 和已处理的最新 `UR-NNNN`；未记录的新需求不得被声称已归一化或已实现。
